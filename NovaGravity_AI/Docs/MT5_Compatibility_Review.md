# مراجعة توافق NOVA GRAVITY AI مع منصة MetaTrader 5 — تحديثات المنصة

> **تاريخ المراجعة:** 2026-08-25 · **نطاق المراجعة:** إصدارات MT5 الحالية (المبنية على المنشورات الرسمية حتى Build ~5660، فبراير 2026) · **الهدف:** تجنّب أخطاء الترجمة/التشغيل عند بناء البوت.

---

## 1) ملخص الحكم النهائي

| البند | الحالة |
|---|---|
| التوافق مع الإصدارات الحالية (builds 5100 → 5660+) | ✅ متوافق |
| الحاجة لأي تغيير في البوت بسبب تحديثات 2025/2026 | ❌ لا يوجد — راجع البنود أدناه للتحقق |
| النقاط التي **تجب مراعاتها عند أي تطوير مستقبلي** | ✅ موثقة في §3 |

**الخلاصة:** لا توجد واجهات برمجية (API) تم حذفها أو تغيير توقيعاتها في النطاق الذي يستخدمه هذا البوت. القواعد الصارمة الجديدة التي أضافها المترجم (تفرّد المُعرّفات داخل نفس النطاق، حجب الدوال الموروثة، فحص الأنواع في التعدادات) **تم تطبيقها بالفعل** على الكود: كل عناصر `enum` لها معرفات فريدة (بادئة `NG_`)، ولا توجد أسماء مكررة، ولا استخدام لسلوك الحجب القديم.

## 2) ما تمت مراجعته بالتفصيل

### 2.1 إصدارات حديثة مفحوصة

| الإصدار | تاريخ الإصدار | أبرز التغييرات | أثرها على البوت |
|---|---|---|---|
| **Build 5100** (MetaEditor جديد + Git + MQL5 Algo Forge) | 2025-06 | إعادة بناء MetaEditor، دعم Git، مكتبات OpenBLAS موسعة، `Random()`، أنواع `int64_t/uint64_t`، كشف سمة الألوان `TERMINAL_COLORTHEME_NAME` | لا أثر — البوت لا يستخدم الإضافات، لكنه يُترجم بنجاح في البيئة الجديدة |
| **Build 5120** | 2025-06 | تمرير مصفوفات بإعادة تفسير الموقع (signed/unsigned) في `ArraySwap`, `WebRequest`, `CryptEncode`… وإصلاح `TerminalInfoInteger` و`ArrayInitialize` | إيجابي: لا أثر سلبي |
| **Build 5200** | 2025-08 | **قواعد صارمة فعالة:** قواعد أقوى لحجب دوال الفئات (يجب مؤهل `::`)، **منع الأسماء المكررة في نفس النطاق**، **فرض تطابق نوع القيم الافتراضية للتعدادات**، منع إعادة استخدام معرّف عبر تعدادات مختلفة، تشديد قوالب المصفوفات، إصلاح `OrderCalcMargin` في الـ Tester | **مطبق بالفعل** — راجع §2.2 |
| **Build 5660** | 2026-02 | تحسينات بروكسي (إزالة SOCKS4)، دعم HTTP/SOCKS5، معالجة OpenBLAS | لا أثر — البوت لا يستخدم الشبكة |
| **تحديثات 2026-04** (مصدر What's new) | 2026-04 | إصلاح سلوك `WebRequest` في `OnDeinit`، إضافة دوال `account_info()` / `positions_total()` / `positions_get()` كبدائل، إصلاح تأخير دوال `Copy`/`i-` في إطار `W1` | إيجابي/محايد — البوت يستخدم الواجهات الكلاسيكية العامّية المدعومة دائماً |

### 2.2 التزام الكود بقواعد Build 5200 الصارمة

1. **معرّفات التعداد فريدة عبر كل الكود**: `NG_RISK_*`, `NG_ENTRY_*`, `NG_REGIME_*`, `NG_FRIDAY_*`, `NG_CLASS_*` — لا يوجد أي تكرار مع أسماء المدخلات أو الدوال. ✅
2. **لا أسماء مكررة داخل نفس النطاق**: فحص آلي (85 input + كل الدوال/المتغيرات العامة) لا يوجد تكرار. ✅
3. **قيم افتراضية للتعدادات بالنوع الصحيح**: `ENUM_NG_RISK_MODE InpRiskMode = NG_RISK_PERCENT;` — القيمة من نفس التعداد (وليس رقماً صريحاً). ✅ (ملف `.set` يُخزّن الأرقام — هذا طبيعي لأن استيراد الإعدادات يُحوّلها عبر محرّر الخصائص، وهو سلوك MT5 الرسمي.)
4. **حجب الدوال الموروثة**: البوت لا يستخدم الإرث، لكن دعائمه (`CTrade`) تُستخدم عبر الكتابة الصريحة `trade.`. ✅

### 2.3 قرارات تصميمية مبنية على قيود المنصة

| القيد المعروف | القرار المطبق |
|---|---|
| `WebRequest` **لا يعمل داخل الـ Strategy Tester** (موثق رسمياً وعلى Stack Overflow) | البوت لا يستخدم `WebRequest` إطلاقاً؛ الأوامر كلها محلية. لوحة التحكم تعتمد على **ملفات تقارير Tester المصدّرة (HTML/CSV)** بدلاً من أي جلب شبكة. ✅ |
| قواعد `MQL_INFO`/`MQL_TRADE_ALLOWED` غير مفعّلة داخل الـ Tester | فحص حالة التداول يُتجاوز عند `MQL_TESTER == true` حتى لا يفشل الاختبار في المنصة. ✅ |
| أوضاع التعبئة غير متوفرة لدى كل الوسيط | البوت يجرب ترتيبياً `FOK → IOC → RETURN` حسب `SYMBOL_FILLING_MODE` — الطريقة الموصى بها للتوافق مع كل الوسطاء. ✅ |
| `PositionClosePartial` لا يوجد في الإصدارات القديمة جداً | البوت يطلب إصداراً حديثاً (كل الإصدارات المعتمدة 2025+)؛ لو استُخدم على build قديم جداً انتبه للترقية. ✅ |
| رموز بخطوة حجم غير قياسية (0.001 / 1.0) | الحجم يُقرّب حسب `SYMBOL_VOLUME_STEP` الحقيقي وليس منزلتين ثابتتين (إصلاح #9 من ملاحظاتك). ✅ |
| توقيت السيرفر يختلف عن GMT | `InpServerGmtOffset` (افتراضي **999 = كشف تلقائي** من `TimeTradeServer() - TimeGMT()`). ✅ |

## 3) تحذيرات وصيانة مستقبلية (مهم)

1. **قبل كل تحديث منصة**: افتح `MetaEditor → Help → What's new` وتأكد ألا يظهر أي بند عن `Trade`, `Position*`, `Order*`, `CTrade`, `iMA/iRSI` — هذه الواجهات مستقرة منذ 2016 ولم تتغير، والتغييرات الأخيرة اقتصرت على مكتبات رياضية/شبكة/واجهة.
2. **إمضاء البوت (Signature)**: البوت لا يحتاج `WebRequest` ولا مكتبات خارجية ولا DLL — لذلك لن يُمنع من التداول الآلي، وسيُترجم نظيفاً مع `#property version "1.00"`.
3. **Strategy Tester**:
   - استخدم **"Every tick based on real ticks"** لنتائج واقعية للسبريد/الانزلاق.
   - التقارير المُصدّرة من `Test → Report → Export (HTML)` هي المتوقعة في لوحة التحكم (متوافقة مع بنية `<table>` التي يصدّرها MT5: أعمدة Ticket / Open Time / Type / Size / Item / Price / S / Close Time / Price / S / Commission / Swap / Profit / Balance).
   - انتبه: عمود `S` في تقرير MT5 قد يظهر بعنوان "S" أو فارغاً — المحلّل يدعم الصيغتين، كما يدعم استيراد CSV يدوي بالأعمدة الموضحة داخل اللوحة.
4. **إعدادات `.set`**: تُستورد عبر `خصائص الخبير → تحميل`، وأُجريت مزامنة كاملة بينها وبين ملف Excel (كلاهما مولّد آلياً من نفس مصدر الكود — ضمان عدم الانحراف).
5. **هوية الملفات**: لا تغيّر `#property copyright` أو `version` داخل الكود بعد توزيع النسخة — مهم لتشخيص أخطاء المستخدمين.
